How I work

Four habits behind every release I sign off

risk-based

Test where the risk is

Not every screen deserves the same attention. I map where failures would hurt most, like payments, login and identity checks, and put the deepest coverage there first.

ci/cd

Make quality part of the pipeline

Automated suites in Playwright, Appium and Testsigma run on every change, so teams find problems in minutes instead of during a long manual regression.

quality gates

Release on evidence

Go/no-go decisions rest on numbers everyone can see: defect leakage, automation coverage and release readiness, tracked in shared dashboards.

people

Raise the whole team

I've mentored 10 QA/SDET engineers and work closely with product, engineering and compliance, so quality is a shared goal and not a final checkpoint.
